The "Vague Input" Loop: Users often give bad prompts (e.g., "Make me a YouTube").

Solution: The Requirement Engine must have a "Clarity Gate." If the confidence score of the extracted requirements is low, the agent should stop and ask the user questions instead of guessing.







Phase 1: The Design Doc (The Logic)
User Input: You type in what you want to build.

Requirement Classifier:

Calls Tools: Calculates numbers (RPS, storage size).

RAG: Looks at real-world examples (e.g., Netflix, Uber) to find similar cases.

Output: Creates a list of "Tags" (like High-Traffic or Database-Heavy).

System Architect:

RAG: Uses the tags to find the best tools (like Kafka, Redis, or SQL) from a scalability library.

Output: Writes a detailed text document explaining the design.

Logic Auditor: Reads the document. If it finds a mistake, it sends it back to the Architect to fix.

Phase 2: The Diagram (The Visual)
Diagram Agent: * Takes the approved text document.

RAG: Uses pre-made code snippets to ensure the diagram looks professional.

Output: Generates Mermaid.js code.

Diagram Verifier: * Checks if the code is broken. If it is, the AI fixes the code automatically.

Visual Auditor: * Makes sure the final drawing actually matches what was written in the text document.

Final Output: The user sees a perfect High-Level Design (HLD) and a professional diagram.
